# 14 A2A

> 分组：协作与派遣

**A2A 协作：跨进程代理的标准化握手** —— Step13 的子代理是自家分身（同进程）；A2A 解决的是跨进程、跨主人的协作 —— 名片发现、标准信封、task_id 回执。

## 核心概念 {#concept}

### 子代理 vs 外部代理

主代理直接 new 出来的子代理，活在同一个进程里，共享宿主的模型与工具。而网络上还有**别人家的代理**：翻译代理、天气代理…… 它们有自己的实现，你不了解也不需要了解。类比：**请同事帮忙 vs 外包给合作公司**。

::: tip 💡 一句话理解
A2A = 代理之间的 REST。发现靠名片（Agent Card），调用靠统一信封（task_id + 状态机），不猜对方的内部接口。
:::

### A2A 协议的三块基石

| 基石 | 内容 | 本场景对应 |
| --- | --- | --- |
| **名片发现** | Agent Card：name / url / version / skills，生产中托管在 `/.well-known/agent.json` | `a2a_discover` 拉取 translator、weather 两张名片 |
| **标准信封** | task_id + submitted → working → completed/failed 状态机 | `a2a_send` 发送任务，返回 task_id + 回执 |
| **异步回执** | 发起方拿 task_id 即可离开，结果异步取回 | 响应里带 task_id，状态流转展示在轨迹里 |

### 和 Step13 的分工

| 维度 | 23 · 子代理 | 25 · A2A |
| --- | --- | --- |
| 运行位置 | 同进程（in-process） | 跨进程、跨网络 |
| 上下文 | 可 spawn 全新 / fork 继承父会话 | 对方独立，只能靠任务描述传递 |
| 信任模型 | 自家代码 | 标准协议 + 名片声明的能力边界 |

### 试试这样玩

- 「发现一下附近的代理」—— 看两张名片的 url / version / skills；
- 「让翻译代理把「你好，智能体」翻译成英文」—— 观察轨迹：名片路由 → submitted → completed 回执；
- 注意 task_id —— 生产中发起方靠它轮询/订阅结果，而不是傻等。

生产化路径：名片加认证与签名校验、长任务轮询/回调、失败重试与幂等、生产级框架 的 CollaborationController 还支持多代理编排请求。

## 实现要点 {#impl}

### 本场景的骨架

a2a_discover 拉名片 → 按 skill 路由 → a2a_send 发信封 → task_id 回执

```java
// 名片：A2A 的发现单元（生产中是 .well-known/agent.json）
record AgentCard(String name, String url, String version,
                 List<String> skills, String description) {}

// 发送：按名片路由 + 状态机流转（发起方只认 task_id）
String taskId = "task-" + seq + "-" + uuid4();
//  submitted → working → completed
return "{"task_id": "" + taskId + "", "status": "completed", "result": "" + reply + ""}";
```

## ToyAgent vs ToyAgentScope {#compare}

**A2A：真·跨代理协议** —— 两个「远端」智能体用 AgentScopeA2aServer 发布在 /a2a/{name}；协调者通过 Agent Card 发现它们，再用 A2aAgent 走 JSON-RPC 协作。

GET /a2a/translator/.well-known/agent-card.json → A2aAgent.call() → POST JSON-RPC message/stream → SSE 任务事件 → 回复

### 服务端：把智能体发布成 A2A 服务

```java
AgentScopeA2aServer server = AgentScopeA2aServer.builder(reactAgentBuilder)
        .agentCard(new ConfigurableAgentCard.Builder().name("translator").description("中英互译代理").build())
        .deploymentProperties(new DeploymentProperties("localhost", port, "/a2a/translator"))
        .build();
// 它不监听端口，只提供 TransportWrapper —— 由我们的 HttpServer 把请求交给它
Object result = server.getTransportWrapper("JSONRPC").handleRequest(body, headers, Map.of());
// 非流式 → JSON；流式（message/stream）→ Flux，逐条写成 SSE 的 data: 行
```

### 客户端：远端代理就是一个普通 Agent

```java
A2aAgent remote = A2aAgent.builder()
        .name("translator")
        .agentCardResolver(WellKnownAgentCardResolver.builder()
                .baseUrl("http://localhost:8099/a2a/translator/")      // 注意结尾的 /
                .relativeCardPath(".well-known/agent-card.json")       // 注意开头没有 /
                .build())
        .build();
Msg reply = remote.call(new UserMessage(task)).block();
```

::: warning ⚠️ 实测踩坑：名片 404
A2A SDK 用 `URI.resolve(relativeCardPath)` 拼名片地址。默认相对路径 `/.well-known/agent-card.json` 以斜杠开头，会把 base 里的 `/a2a/translator` 整段丢掉，变成访问主机根路径。多个代理挂在同一主机不同路径时，base 要以 / 结尾、相对路径不能以 / 开头。
:::

::: tip 💡 与 Step13 的区别
子代理是「我造的、在我进程里」；A2A 的对端是**别人的**智能体（可能是 Python、可能是别家框架），双方只约定协议：名片 + JSON-RPC + 任务事件。
:::
